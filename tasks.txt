# Task 5: Unify human-lane accounting  [HIGHEST VALUE - confirm direction with operator first]
Unify human-lane accounting. Asks route through Router.route() yet never produce a TaskMetric, so v_lane_performance carries a human/operator row whose ok_rate is meaningless and whose diverged count is always 0, while real human performance lives in interaction_metric and v_attention_ledger (ADR 32 open note). Investigate, then implement exactly one of: (a) emit a TaskMetric for human asks on resolution, or (b) scope v_lane_performance to model lanes only and drop the vestigial human row. Recommendation is (b) - a human ask has no tokens, cost or VRAM, so a zero-filled TaskMetric would pollute every lane average. If (b), also determine whether ADR 28's divergence-exclusion logic becomes dead code in that view. Add tests in apps/harness/tests/test_dignity.py and record the outcome as ADR 35.
